# AI가 실제로 틀린 패턴과 막는 규칙

운영 중인 시스템에서 AI 코딩 에이전트가 낸 결과를 사람이 잡아낸 실제 사례다. 지어낸 사례는 넣지 않는다.

| 패턴 | 무슨 일이 있었나 | 어떻게 잡았나 | 남긴 규칙 |
|---|---|---|---|
| 화면은 그럴듯한데 비율이 틀림 | 회사 로고의 가로세로 비율을 잘못 잡은 화면을 냈다 | 실제 화면을 눈으로 확인 | 화면 변경은 실기기나 스크린샷 확인을 완료 조건에 넣는다 |
| 입력을 가공 없이 그대로 보냄 | 문자열 태그를 형식 변환 없이 그대로 전송하는 백엔드 코드를 냈다 | 코드 검토 | 외부로 나가는 값은 형식을 테스트로 고정한다 |
| 빈 값을 "없음"으로 판정 | 응답 도착 전의 빈 배열을 "예약 없음"으로 봐서 1~2초 거짓 경고가 떴다 | 사용자 제보 → 재현 | 조회 중·확인 불가·없음을 분리한다 ([원칙 4](principles.md#4-기다리는-동안의-빈-값은-없음이-아니다)) |
| 보고를 성공으로 단정 | 현장 프로그램의 "처리했다" 보고를 알림이 "꺼졌습니다"로 표시했다 | 실제 장비 상태와 대조 | 보고와 관측을 분리한다 ([원칙 3](principles.md#3-보고와-관측을-나눈다)) |

네 가지 모두 실제 화면, 코드 검토, 사용자 제보, 실제 장비 대조로 잡혔다. 자동 테스트는 에이전트가 떠올린 경우만 확인한다. 그래서 완료 조건에 **사람이나 실제 환경이 확인하는 단계**를 하나 이상 둔다.
